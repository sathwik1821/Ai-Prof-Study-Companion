1. Overview & Separation of Concerns

1. Overview & Separation of AI Roles

AiProf Study Companion is an enterprise-grade, full-stack educational platform built to transform unstructured academic documents into grounded, interactive learning journeys. Because Artificial Intelligence played a role in both the engineering process and the resulting user experience, this technical document formally and transparently delineates the two distinct categories of AI involvement:

Mandatory Architectural Separation of Concerns:
  1. AI Used to Build the Product (Category A): Autonomous developer agents, IDE coding assistants, refactoring engines, browser subagents, and automated validation tooling utilized by the developer (Sathwik Bodakunta) during software engineering.
  2. AI Embedded in the Final Product (Category B): Production inference models (Google Gemini Flash Lite, Gemini Embeddings) and vector database infrastructure (PostgreSQL pgvector) that execute inside the live deployed application to deliver tutoring, adaptive quizzing, and document RAG to end-users.

5. Technical Details of Product AI Features

5. Product AI Feature Details

5.1 Socratic AI Tutor

  • User Input: The student inputs an inquiry or concept question in the tutor chat interface.
  • Request Flow: Dispatched via POST /api/projects/{id}/tutor/chat with the question text.
  • Backend Construction: TutorService checks for uploaded course materials. If zero documents exist, it throws NO_MATERIALS and halts inference. If documents exist, it converts the prompt into a 3072-dimensional vector via RagService.getEmbedding(prompt), queries document_chunks using cosine distance (<=>), and retrieves the Top 6 matching excerpts.
  • Socratic Prompt Construction: 
    You are an expert academic tutor. Context excerpts from verified course materials:
[Chunk 1]: ...
[Chunk 2]: ...
Student Question: {userPrompt}
Instructions:
1. Do not give the solution directly. Use Socratic dialogic questioning.
2. Formulate a targeted question or hint that leads the student toward discovery.
3. Explicitly cite chunks using: [Citation: filename (chunk #)].
  • Output Processing & Presentation: The response is parsed for citation tags, persisted in chat_messages, and rendered in TutorPage.jsx with interactive citation badges that highlight the original document excerpts.

5.2 Adaptive Diagnostic Quiz Generation

  • User Input: Student clicks *"Generate Practice Quiz"* inside a course project.
  • Processing Logic: QuizService gathers representative semantic chunks across all project materials. It queries Gemini Flash Lite with a structured JSON schema prompt specifying question count, question type (Multiple Choice, True/False, Short Answer), options, correct answers, explanations, and target concept tags.
  • Validation & Persistence: Backend validates that generated options contain valid keys and a non-empty correct answer, persisting them in quizzes and quiz_questions tables.
  • Student Presentation: QuizPage.jsx provides an interactive assessment runner with per-question timers, option selection, immediate conceptual rationales, and grading breakdowns.

5.3 Concept Mastery Tracking & Prescriptive Recommendations

  • Scoring & Updates: Upon quiz submission (POST /api/quizzes/{id}/submit), the backend computes percentage accuracy and updates the student's mastery score in concept_mastery using an exponential moving average:
    New_Mastery = (Old_Mastery × 0.4) + (Attempt_Score × 0.6)
  • Targeted Recommendation Engine: MasteryService identifies concepts with mastery score < 70%. If a weak concept exists, the Dashboard highlights it in the **Targeted Mastery Recommendation Card** (e.g. *"Concept Retention • Binary Search (35%)"*), routing the student directly to focused quiz practice or tutor questioning with a single click.

7. Responsible AI Usage & Governance

7. Responsible AI Usage & Governance

  • Human Code Auditing: Every AI-suggested code snippet was reviewed for architectural soundness, memory efficiency, and security before being integrated into git.
  • Prevention of Hallucinations via Grounding: The Socratic AI Tutor strictly references ingested documents. If a query falls outside the project's source materials, the system guardrail explicitly directs the model to decline answering rather than inventing facts.
  • Empty Materials Gate: Prevents ungrounded inference by enforcing that a student must upload at least one verified course document before accessing tutoring or diagnostic quizzes.
  • Zero Secret Exposure: No API keys, OAuth client secrets, or database passwords are hardcoded in git. All sensitive credentials are provided dynamically via environment variables (GEMINI_API_KEY, JWT_SECRET).
  • Pedagogical Safeguards: Prompts enforce interactive questioning rather than homework-solving shortcuts, fostering genuine learning and cognitive retention.

8. Limitations & Lessons Learned & 9. Summary

8. Limitations & Lessons Learned

8.1 Technical Limitations Encountered

  • Cloud Firewall Restrictions on Outbound SMTP: Render's free tier firewalls block outbound raw TCP traffic on ports 25, 465, and 587. Even with valid Gmail credentials, direct SMTP fails. This necessitated engineering an HTTP REST email transport via Resend (HTTPS port 443) and implementing dev-code auto-fill fallbacks.
  • React Hook Order Determinism (Error #310): AI code generation initially placed a useMemo hook below an early if (loading) return skeleton check in DashboardPage.jsx. In production, this caused a fatal React crash on re-render. Resolving this reinforced the importance of human code review regarding React's strict Rules of Hooks.
  • Embedding Dimensions & Schema Alignment: Google's gemini-embedding-001 outputs 3072-dimensional vectors. Schema migrations had to explicitly align the PostgreSQL column type to VECTOR(3072), requiring specialized Flyway DDL coordination.
  • Single-Origin OAuth Restrictions: Google Identity Services strictly rejects origins not pre-registered in Google Cloud Console. Transitioning between preview URLs required developer intervention to authorize Vercel production domains.

8.2 Key Lessons Learned

  • AI Tools Require Technical Guidance: AI assistants are highly capable of generating boilerplate and diagnosing errors, but cannot replace architectural judgment, domain modeling, or comprehensive verification.
  • RAG Quality Depends on Chunking Strategy: A 400-token window with 50-token overlap provided the optimal balance between granular vector cosine similarity and contextual comprehension for academic text.
  • Stateless Architecture Ensures Seamless Deployment: Decoupling the Vite/React frontend onto Vercel's edge network and the Spring Boot backend into Render's container runtime ensured zero coupling and clean independent scalability.
